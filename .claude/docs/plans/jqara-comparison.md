# 検証計画: Jev は RAG の検索精度を上げるのか

## 問いと答え方

問い。Jev を検索の並べ替えに使うと、従来のRAG（埋め込み検索、および既製のリランカー）より上位に正解を集められるか。

答え方。同じ質問、同じ候補、同じ指標で6経路を並べる。候補を並べ替える課題に統一することで、経路間で変わるのが「順位の決め方」だけになる。

## 素材

JQaRA テストセット。1,667問、各100候補、正解ラベル付き（正解は中央値8件）。本文は最大400字。ライセンスは CC-BY-SA-4.0（JAQKET）と Wikipedia の CC BY-SA 4.0 / GFDL。

正解ラベルを自作しないことが要点。検索の比較で最も恣意的になるのがラベルの作り方で、そこを公開データに委ねる。副次的に、公開されている日本語リランカーのスコアと同じ土俵に乗る。

## 指標

nDCG@10 を主指標とする。JQaRA の公開スコアがこの指標なので、外部の数字と直接比べられる。補助として MRR@10（最初の正解が何位に来たか）と Recall@10（正解を何割拾えたか）。

参考値（公開されている JQaRA テストセットの nDCG@10）:

| model | nDCG@10 |
|---|---|
| multilingual-e5-large（埋め込み） | 0.554 |
| GLuCoSE-base-ja-v2（埋め込み） | 0.606 |
| ruri-large（埋め込み） | 0.629 |
| japanese-reranker-cross-encoder-large-v1 | 0.710 |
| ruri-reranker-base | 0.743 |
| ruri-reranker-large | 0.771 |

Jev がこのレンジのどこに入るかが、記事の結論の中心になる。

## 経路

1. `embedding` — Cohere Embed v4 の類似度順。従来のRAGそのもので、比較の基準。
2. `cohere_rerank` — Cohere Rerank v3.5。従来の再ランキング。
3. `jev_pointwise` — 候補ごとにNoulを1問。共有stateに全候補を置く。
4. `jev_crossencode` — 候補1件ごとにリクエストを分ける。公式cookbookの手順。
5. `jev_pairwise` — 2候補のChoiceを繰り返し、勝率で並べる。
6. `jev_hybrid` — 埋め込みの順位とJevの判定を融合。

文脈選択（5つ目のユースケース）は順位ではなく採否なので別枠。削減した文字数と、残った正解の割合で測る。

## 手順

1. `jev-rag prepare`
2. `jev-rag evaluate --queries 10 --candidates 30` で動作と費用を確認
3. `jev-rag evaluate --queries 300 --candidates 30` で本測定
4. 差が小さい経路があれば `--candidates 100` で確定させる
5. `jev-rag report --movers jev_crossencode` で具体例を抽出
6. `jev-rag context` で文脈選択を測定

## 記事の構成案

1. 問い。RAGの検索結果、上位に本当に欲しい文章が来ているか。
2. 従来手法の限界を1例で示す。`--movers` から、語彙は似ているが答えでない文章が上位に来ている質問を1つ引く。
3. Jev とは何か。生成ではなく型付きの判定を返すモデル。3つの問いの形（Noul / Choice / Score）。
4. 公式が挙げる5つの使い方と、それぞれをどう実装したか。コードは短く1経路1スニペット。
5. 結果表。6経路 + 公開スコアの参考値。
6. 順位が上がった具体例。
7. 文脈選択の効果。
8. 注意点。日本語での性能に関する公式の但し書き、指示文の調整をしていないこと、候補シャッフルの話。
9. 費用と速度。

## この計画の弱点

指示文を調整していない。従来手法は既製サービスをそのまま呼ぶのに対し、Jev側は指示文の書き方に結果が左右される。初期値のままだとJevを低く見せる可能性があり、逆に磨きすぎると不公平になる。どちらの立場を取るか記事で明示する。

日本語。公式が英語以外は同等でないと明記している。この検証は日本語のみなので、結論は日本語に限定される。英語データセットでも測れば一般性は上がるが、作業量は倍になる。

単一データセット。JQaRA は Wikipedia を対象としたQA検索で、業務文書の検索とは性質が違う。結論をそのまま社内RAGに一般化はできない。
