# 指標を比べる前に確かめること

新しい判定器を測ったら、指標を比べる前に、確率の分布（同じ値の多さ、0.00 や 1.00 への偏り）を見る。

確率に同点が多いと、指標ごとに同点の扱いが違い、同じデータから別の結論が出る。2026-10-19、Decisions API の比較で、`decisions_crossencode` の確率は J-RAGBench の 82% が 0.00 だった。経路は同じ確率の候補を 4 段階の評価で並べ分けていたのに、問題ごとの PR-AUC は確率だけで計算していた。そのため同点がかたまりとして扱われ、Jev との差が −0.128 と出ていた。経路が実際に返した順序で計算すると、差は −0.006 だった。上位 k 件の割合は並べ分けた後の順で数えていたので、「1 位はほぼ同じなのに PR-AUC だけ差がある」という食い違いになって表れた。

対策として、`score_pairs` は経路が同点を並べ分けるのに使った値（`grade`）を保存し、並べ替えの指標は（確率、評価）の順で計算する（`judge_report._order_key`）。しきい値で切る指標（全問まとめた PR-AUC、ECE）は確率だけで計算する。しきい値は確率に対してかけるので、こちらは同点をそのまま扱うのが正しい。

指標どうしで食い違いが出たら、その理由を確かめてから記事に書く。
