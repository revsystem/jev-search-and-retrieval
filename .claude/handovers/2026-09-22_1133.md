## 決定事項
- state 参照はバックティック付きのドット・インデックス記法、state ルートからの相対パス（例 `` `candidates[3].text` ``）。`state.` 接頭辞は付けない。候補は配列で渡し位置で参照する
- Choice の選択肢キーはモデルに見えるので、doc_id ではなく中立ラベル（a / b）を使い、説明文でパスを示す
- pairwise は比較ごとに1リクエスト。全候補を共有 state に置く形は採らない
- パッセージは `f"{title} {text}"`。JQaRA 公式評価と同じ形にする
- `.env` の秘密情報は Jev の鍵1つだけ。AWS は `AWS_PROFILE` + `aws sso login` で、鍵は書かない
- 既に export されている環境変数は `.env` より優先する
- 記事の主題は「Jev が効くか」ではなく「リクエストの形が支配的な変数である」。同じモデル・同じ候補・同じ指示文で 0.21 と 0.90 に分かれる

## 捨てた選択肢と理由
- 白書PDFを素材にする案: PDF抽出のアーティファクト処理と正解ラベルの自作が検証の本筋でないうえ、結果の説得力も落ちる — JQaRA（正解ラベル付き、公開スコアあり）に替えた
- ゼロから作り直す案: 公式ドキュメントと照合済みの Jev 実装まで作り直すことになり手戻りが大きい — 素材まわりだけ差し替え、`src/jev_rag/jev/` は残した
- S3 Vectors を比較経路に含める案: JQaRA は候補が最初から与えられる課題なので、ベクトルストアは比較に不要。無理に挟むと複雑さだけ増える — 比較の本筋から外した（モジュールは未使用のまま残っていない。dataset 化の際に削除済み）
- 候補を dict（doc_id をキー）で state に渡す案: `candidates.5191928` は数値キーへのドットパスで、公式の例にない形 — 配列＋インデックスにした
- `npx skills add` でスキル導入を迂回する案: 分類器が拒否した行為を別ツールで通すのは迂回にあたる — raw URL からスキル本文を読む方法（指示文に併記されていた代替手段）を採った
- 候補10件で測る案: k=10 なので正解が全部カットオフ内に入り、nDCG@10 も recall@10 も水増しされる（embedding が 0.868 と出た）— 公開スコアと同じ候補100件にした
- `--candidates` 絞り込みで正解を先頭に残す案（シャッフルなし）: 入力順が正解を漏らし、何もしない経路が満点になる — 問題ごとの固定シードでシャッフルする

## ハマりどころ
- `claude plugin marketplace add` が拒否される → auto mode の分類器が Untrusted Code Integration と判定 → raw URL からスキル本文を読んで適用。プラグインとして入れるには Bash 権限ルールの追加が必要
- pointwise が候補100件で 0.21 まで落ちる → バグではなく公式に記載のある失敗モード（「Large state full of irrelevant detail」）。候補100件を1 state に入れると各質問にとって99件が妨害情報になる → バッチサイズを変数として扱い、クロスエンコード（batch=1）を既定の推奨形にした
- zsh の `noclobber` で `cat >> newfile` が「no such file or directory」で失敗する → 新規ファイル作成には Write ツールを使う
- zsh の `cp -i` エイリアスでファイル復元が対話待ちで止まる → `git checkout -- <path>` で戻す
- heredoc を `cmd1 <<'PY' || cmd2 <<'PY'` の形で二重に書くと片方しか適用されない（無言で失敗する）→ 絶対パスの python を1回だけ呼ぶ
- `grep --include='*.py'` は zsh でクォートしないとグロブ展開で失敗する

## 学び
- Jev の質問IDはモデルに送られない。どの候補についての判定かを伝えられるのは instructions だけ。参照記法を外すと静かに精度が落ち、「日本語が苦手」に見える
- リクエストの形が精度を支配する。候補100件・同一 state の listwise が 0.21、候補1件ずつのクロスエンコードが 0.90。公式 cookbook が後者を採るのはこのため
- ただしクロスエンコードは1問あたり約11.7秒・100リクエスト。cohere_rerank は0.7秒・1リクエスト。費用（入力100万トークン$0.042）は無視できる水準で、効くのはレイテンシとレート制限。対話的なRAG経路には載らない
- 配列インデックスでパスを組むと、質問キー（doc_id）とパス（位置）が別のキーになる。ズレると全候補が静かに誤採点されるので、インデックスが質問キーの指す文書に解決することをテストで固定する必要がある
- JQaRA 公式評価は `f"{title} {text}"` を連結する。本文だけ採点すると公開スコアと同じ土俵に乗らない
- Cohere Embed v4 の JQaRA nDCG@10 は 0.609（10問）で、公開値のレンジ 0.554〜0.629 に収まる。ベースラインの妥当性確認に使える
- ast-grep はコード検索に使う（ユーザー指示）。文字列リテラル内の検出は `kind: string` + `regex` で構造的にできる
