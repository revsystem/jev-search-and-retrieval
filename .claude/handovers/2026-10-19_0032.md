## 決定事項
- API キーはリポジトリの `.env` に置く。`~/.zshrc` は dotfiles リポジトリの `home/.zshrc` への symlink で、commit すると鍵が公開されるため
- 派生元はデフォルトブランチ。`feat/strands-decider-comparison` は記事のリンク先として残すもので、今回の比較とは独立させる
- Jev も Decisions も同じ日に最新のモデルで測り直す（ユーザーの決定）。Jev は `JEV_DIRECT_MODEL=jev-1.14.0` で固定する
- 経路は Jev 3 つ（`jev_pointwise`、`_plain`、`jev_crossencode`）と Decisions 3 つ（`decisions_pointwise`、`_plain`、`decisions_crossencode`）。埋め込みと Cohere Rerank は測り直さない
- 判定基準は Decisions に `criteria` の欄がないので `instructions` の末尾に足す。記事に違いとして書く
- Decisions の質問名は位置（`c0`…、`relevance`、`grade`）にする。name の文字の規則が文書化されていないため
- 本測定の前に順序の入れ替え確認をする。1 件ずつの経路を揺れの基準として先に読み、それが基準（差の中央値 0.1 以下、スピアマン 0.8 以上）を満たさなければ判断をユーザーに仰ぐ。まとめる経路が 1 件ずつより 0.2 以上低ければ不合格
- `refusal` と欠けた答えは 0.0 にしたうえで件数を表示する。応答の `model` と `usage.input_tokens` を両 API で保存する
- Decisions の SDK は `max_retries=2`・`timeout=60`（Jev の HttpTransport の 3 回・60 秒とそろえる。レビューの指摘）
- report-judge の Decisions − Jev の差と区間は、両経路が答えた問題の共通部分で計算する
- `uv.lock` は commit し、README のインストール手順を `uv sync --extra dev` に変えた（ユーザーの決定、9a475a9）
- untracked の `CLAUDE.md` は commit せず、untracked のまま残す（ユーザーの決定）
- 出力は `out/decisions/`。`results/` と既存の `out/` は変えない
- herdr で調査とレビューを codex（wP:p7）と cursor（wP:p8）に分担する（ユーザーの承認）。codex は無料プランなので、使用上限に当たったら新しいペインを分割してエージェントを起動する（ユーザーの指示）

## 捨てた選択肢と理由
- `~/.zshrc` にキーを置いたままにする案: dotfiles リポジトリで管理されており、commit で鍵が漏れる — リポジトリの `.env` に移した
- `feat/strands-decider-comparison` から派生させる案: 記事のリンク先として固定したいブランチで、比較対象も違う — デフォルトブランチから派生させた
- 記事の Jev の結果（`results/`）を再利用して Decisions だけ測る案（Claude の推奨案）: 10 月 14 日に Jev 1.14.0 が出たため、ユーザーが両方を最新で測り直すと決めた — 同じ日に両方を測る
- `jev-latest` で測る案: 2026-10-19 時点で `jev-latest` は `jev-1.13.0` を指す — `jev-1.14.0` に固定する
- 質問名に文書 ID を使う案（仕様書の初版の例）: name の規則が未記載で、MIRACL の ID などが衝突しうる — 位置の名前にした
- レビューで見送った指摘: 例外時のリクエストを `requests` に数える（表で使わない）、long-context の料金乗数（272K 超のリクエストだけが対象）、Jev の 0 トークン表示と Jev だけ件数が可変（どちらも Task 9 Step 3 の確認で見る）

## ハマりどころ
- Decisions API が 403 → `.env` のキーが制限付きで `api.decisions.write` の権限がない → ユーザーがダッシュボードで権限を付けて解消
- TypeSafe のクレジット切れで Jev が 402 `billing_error` → 失敗した問題は `score_pairs` の `failed` にしか残らず理由がわからない → preflight で気づいた。ユーザーがクレジットを追加して解消
- テストの流し方 → `.claude/lessons/testing.md`
- zsh の `noclobber` で `>` による上書きが拒否される → `>|` を使う
- `uv sync` は lock にないパッケージを .venv から消す。strands-decider 用の tokenizers などが消えたので、`feat/strands-decider-comparison` に戻るときは sync し直す
- `/api/reference/llms.txt` に Decisions のページがない → SDK の型定義で欄を確かめた
- zsh の `cp -i` エイリアスで上書きが止まる → `command cp -f`。`diff` は壊れた関数なので `command diff`
- ガイドと SDK で画像入力の記述が食い違う → テキストしか送らないので影響なし。資料の README に記録した
- herdr で cursor のペインへの最初の依頼が `agent_prompt_stalled` になり入力も残らなかった → 同じ依頼を再送したら受理された
- codex が最初、Decisions の score に `minimum` / `maximum` を指定すると説明した → SDK 型とガイドでは `levels` 方式で、codex 自身が誤りと訂正した。エージェントの調査結果は一次資料で裏を取る

## 学び
- Decisions API の応答に所要時間の欄はない。`usage` には `input_tokens` と内訳、`output_tokens` がある
- Decisions は質問 1〜200 問、`choice` は 2〜255 択、`score` は `levels`（label と任意の description）。課金は入力 $0.10/1M トークンのみ（2026-10-19）
- 制限付きの OpenAI API キーでは、Decisions に `api.decisions.write` の権限が別に要る（2026-10-19 に 403 で観測）
